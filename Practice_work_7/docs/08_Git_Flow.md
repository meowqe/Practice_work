# Git Flow в проекте MyOS

## Схема ветвления

```
main      ●─────────────────────────────●──────────  стабильная версия
           \                           /
hotfix      \                  ●──────●               срочные исправления (от main)
             \
develop       ●───●─────●───────●───●─────────────    интеграция функций
                   \   / \     /
feature/*           ●─●   ●───●                       отдельные функции
```

## Ветки проекта

| Ветка | Назначение | Создаётся от | Вливается в |
|-------|-----------|--------------|-------------|
| `main` | Стабильная версия, которую можно сдавать/выпускать | — | — |
| `develop` | Интеграция новых функций | `main` | `main` (релиз) |
| `feature/<название>` | Одна функция или задача | `develop` | `develop` (через PR) |
| `hotfix/<название>` | Срочное исправление ошибки в `main` | `main` | `main` и `develop` |

## Ветки, используемые в работе

- `feature/low-stock` — функция `get_low_stock` (US-1).
- `feature/total-v1`, `feature/total-v2` — две версии `total_sum` (для демонстрации конфликта).
- `feature/search-advanced` — функция `search_advanced` (US-2), вливается через Pull Request.
- `hotfix/cart-total` — исправление `cart_total` в `main`.

## Правила

1. Прямые коммиты в `main` запрещены, кроме слияния `hotfix` и релиза из `develop`.
2. Новая функция — всегда отдельная `feature/*`-ветка от `develop`.
3. Сообщение коммита начинается с номера задачи: `US-1: ...`.
4. После слияния ветка `feature/*` или `hotfix/*` удаляется.
5. Hotfix обязательно вливается и в `main`, и в `develop`, чтобы исправление не потерялось.
