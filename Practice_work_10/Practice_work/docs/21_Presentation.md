Итоговый проект, версия 1.0

# Слайд 2. Цель и задачи

**Цель:** создать консольное приложение для учёта и продажи спортивных товаров и оформить полную документацию.

**Задачи:**
- реализовать каталог с поиском, сортировкой и контролем остатков;
- реализовать корзину и оформление заказов со скидкой;
- хранить данные и заказы в JSON;
- считать аналитику: выручка, топ товаров, остатки;
- покрыть код тестами и подготовить сборку;
- вести разработку по Git Flow и выпустить релиз v1.0.

# Слайд 3. Архитектура

```
              ┌─────────────────────┐
              │  main.py  (CLI)     │   разбор команд, вывод
              └──────────┬──────────┘
        ┌────────┬───────┴──┬──────────┐
        ▼        ▼          ▼          ▼
   ┌────────┐ ┌──────┐ ┌────────┐ ┌───────────┐
   │catalog │ │ cart │ │ orders │ │ analytics │   бизнес-логика (src/)
   └────────┘ └──────┘ └───┬────┘ └───────────┘
                           │ использует cart_total
        └──────────┬───────┴──────────┘
                   ▼
            ┌─────────────┐
            │  storage    │   чтение/запись JSON
            └──────┬──────┘
                   ▼
        data/products.json, cart.json, orders.json
```

- Логика отделена от интерфейса: все функции в `src/` тестируются без консоли.
- Данные: словари и списки, хранятся в JSON (без БД и внешних библиотек).

# Слайд 4. Основные функции

| Модуль | Возможности |
|--------|------------|
| catalog | просмотр, сортировка, `search_advanced`, `get_low_stock` |
| cart | добавление с проверкой склада, удаление, итог корзины |
| orders | скидка 0–100%, списание остатков, нумерация заказов |
| analytics | категории, средняя цена, выручка, топ товаров |
| storage | сохранение и загрузка каталога и заказов |

27 публичных функций описаны в `docs/17_API_Reference.md`.

# Слайд 5. Демонстрация

```
python main.py search adidas --min-price 2000 --max-price 5000
python main.py cart add "Спортивный рюкзак"
python main.py cart add "Футбольный мяч" -q 2
python main.py cart show                  # Итого: 8200 руб.
python main.py checkout --customer "Иван Петров" --discount 10
                                          # Заказ №1 оформлен. Сумма: 7380 руб.
python main.py analytics                  # выручка: 7380 руб.
python main.py cart add "Лыжи"            # Ошибка: Товар 'Лыжи' не найден
```

**Слайд 3 (1 мин 10 с).** Архитектура простая и состоит из трёх слоёв. Сверху файл `main.py`: он разбирает команды пользователя и печатает результат, никакой бизнес-логики в нём нет. Ниже четыре модуля с логикой: каталог, корзина, заказы и аналитика. Они ничего не знают о консоли, поэтому их удобно проверять тестами. Модуль заказов использует функцию подсчёта корзины, это единственная связь между модулями. Внизу модуль хранения, который читает и пишет JSON-файлы: каталог, корзину и заказы. Такое разделение даёт запас на будущее: консоль можно заменить графическим интерфейсом, а файлы базой данных, и логику переписывать не придётся.

**Слайд 4 (1 мин 10 с).** Перечислю возможности по модулям. В каталоге товары сортируются по любому полю, а поиск идёт по названию, бренду, категории и диапазону цен одновременно. Отдельная функция показывает товары, которые заканчиваются. Корзина проверяет остаток на складе, поэтому нельзя положить больше, чем есть. При оформлении заказа применяется скидка от нуля до ста процентов, остатки списываются, а заказ получает номер и сохраняется в файл. Причём списание атомарное: если одного товара не хватает, не меняется ничего. Аналитика считает среднюю цену, стоимость остатков, выручку и самые продаваемые товары. Всего в проекте двадцать семь публичных функций, и у каждой есть описание в справочнике API: параметры, результат, пример и возможные исключения.
