# Отладка: get_low_stock

## Где была точка останова
Файл `shop.py`, функция `get_low_stock`, строка `return sorted(low_stock, key=get_total_quantity)` (строка 26).
Запуск: F5, конфигурация «Python File». Тестовые данные: товар A (`sizes: {40: 1, 41: 1}`) и товар B (`sizes: {40: 10, 41: 10}`).

## Значения переменных в момент остановки (панель Variables)
| Переменная | Значение |
|---|---|
| `products` | `[{'name': 'A', 'sizes': {40: 1, 41: 1}}, {'name': 'B', 'sizes': {40: 10, 41: 10}}]` |
| `product` (последний элемент цикла) | `{'name': 'B', 'sizes': {40: 10, 41: 10}}` |
| `quantity` (для последнего товара) | `20` |
| `low_stock` | `[{'name': 'A', 'sizes': {40: 1, 41: 1}}]` |

## Ход отладки
- **Step Over (F10)** — проход по строкам цикла без захода в `get_total_quantity`.
- **Step Into (F11)** — заход в `get_total_quantity`, видно, как считается `sum(product["sizes"].values())`.
- **Step Out (Shift+F11)** — выход из вспомогательной функции обратно в `get_low_stock`.

## Найденная ошибка
Исходная версия брала остаток только из поля `quantity`: `product.get("quantity", 0)`.
Для товаров, у которых остатки хранятся в `sizes`, поле `quantity` отсутствует, поэтому `quantity` равнялось `0`, условие `0 <= 3` выполнялось, и **любой** такой товар (даже с остатком 20) попадал в «низкий остаток».

**Исправление:** добавлена функция `get_total_quantity(product)`: если есть `sizes`, берётся сумма по размерам, иначе — поле `quantity`. Она используется в `get_low_stock` (фильтр и сортировка) и в `highlight_low_stock`.
