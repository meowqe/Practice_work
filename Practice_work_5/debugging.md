# Описание отладки — Практическая работа №5 «Чудо Обувь»

## 1. Среда
- Редактор: Visual Studio Code, расширение Python (Microsoft)
- Проект: папка `ChudoObuv`, файл `main.py`
- Запуск: `Ctrl+F5` (без отладчика), отладка: `F5`
- Проверка выполнена на Python 3.12

## 2. Как отлаживать программу в VS Code
1. **Точка останова (breakpoint)** — клик слева от номера строки (красная точка) или `F9`.
2. **Запуск отладки** — `F5` → «Python File». Выполнение остановится на точке.
3. **Шаги:** `F10` — перейти на следующую строку (не заходя в функцию), `F11` — войти в функцию, `Shift+F11` — выйти из функции, `F5` — продолжить до следующей точки.
4. **Панель Variables** — текущие значения переменных (`products`, `cart`, `p`, `item`).
5. **Watch** — можно добавить выражения, например `sum(p['sizes'].values())`.
6. **Debug Console** — ввод выражений на лету, например `total_sum(cart)`.

## 4. Типичные ошибки, на которые стоит обращать внимание
| Ошибка | Причина | Как исправить |
|---|---|---|
| `IndentationError` | неверные отступы | 4 пробела на уровень; `Shift+Alt+F` форматирует код |
| `NameError: name 'x' is not defined` | переменная не объявлена или объявлена ниже места использования | объявить до использования; соблюдать порядок заданий в файле |
| `KeyError: 'sizes'` | в словаре нет такого ключа | проверить ключи; использовать `.get('sizes', {})` |
| `TypeError: unsupported operand type(s)` | сложение числа и строки (например, результат `input` без `int()`) | приводить тип: `int(input(...))` |
| `SyntaxError` | незакрытая скобка/кавычка, нет `:` после `if/for/def` | смотреть строку, указанную в сообщении |
| Корзина «ломается» после Задания 4 | переменная `cart` в Задании 7 создаётся заново (`cart = []`), у элементов другие ключи (`product` вместо `name`) | это сделано намеренно; `total_sum` использует только `price` и `quantity`, поэтому работает с обеими версиями |
| Кракозябры в консоли Windows | кодировка терминала | запускать из VS Code (UTF-8); при необходимости `chcp 65001` |

## 5. Замечания по коду (не ошибки, но стоит знать)
- В `filter_by_price(products, ...)` параметр `products` затеняет глобальную переменную с тем же именем — работает корректно, но может сбивать с толку.
- `find_user` и `search_products` используют глобальные `users` / `products`; при выносе в модули их лучше передавать параметрами.
- Размеры в словаре хранятся как `float` (`36.0`), поэтому в выводе они отображаются с `.0` — так и задумано в методичке.
